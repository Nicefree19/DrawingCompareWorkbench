# CAD Format Support Policy

Last updated: 2026-05-22 KST

## Purpose

This policy defines the CAD file format support boundary for the Drawing Compare
Workbench after removing ODA File Converter from the product distribution.

The product's comparison truth layer is `CanonicalDrawing`. DXF and DWG import
paths must produce that model before normalization and comparison. DWG support
is limited to the internal read-only reader scope documented below until broader
versions are implemented, validated with real samples, and legally approved.

This document is an engineering policy, not legal advice. Items marked
`법무 검토 필요` must be reviewed before product release or customer delivery.

## 요약

- DXF는 자체 모듈의 직접 지원 형식이다.
- DXF R12, R2000, R2004, R2007, R2010, R2013, R2018은 지원한다.
- DXF R13/R14 및 R12 이전 버전은 읽기 중심 제한지원으로 분류한다.
- DWG는 `AC1015` 단순 2D native reader 범위에서만 제한지원한다.
- 그 외 DWG 버전/객체는 사용자가 CAD 도구에서 지원 DXF로 사전 변환해야 한다.
- ODA File Converter 자동 호출, 번들링, 상용 고객 빌드 의존은 금지한다.
- AC1015 preview를 제품 지원으로 광고하거나, DWG 직접 지원 범위를 확대하거나,
  ODA/상용 SDK/GPL/AGPL CAD 라이브러리를 사용하는 것은 법무 검토 필요 항목이다.

## Support Levels

| Status | Meaning |
| --- | --- |
| 지원 | The product may accept the format directly, parse it in-process, and use it for entity-level comparison. |
| 제한지원 | The product may process the format only under the stated constraints, with user-visible warnings and audit counters where applicable. |
| 미지원 | The product must not claim support. Input must be rejected or routed to a documented external/pre-conversion workflow. |
| 금지 | The format/tool path must not be embedded, redistributed, or enabled in customer builds without explicit legal approval. |

## DXF Version Policy

DXF support is based on `ezdxf` and the current extractor/comparator pipeline:

- Reader: `ezdxf.readfile()`
- Entity extraction: `src/services/comparison/dxf_entity_extractor.py`
- Normalization: `src/services/comparison/entity_normalizers.py`
- Comparison: `src/services/comparison/dxf_comparator.py`
- Rendering preview: `src/services/comparison/dxf_renderer.py`

| DXF version | AutoCAD release | Input policy | Output/export policy | Notes |
| --- | --- | --- | --- | --- |
| `AC1032` | R2018 | accepted | accepted | Preferred modern DXF baseline. |
| `AC1027` | R2013 | 지원 | 지원 | Fully accepted as input. |
| `AC1024` | R2010 | accepted | accepted | Fully accepted as input. |
| `AC1021` | R2007 | 지원 | 지원 | UTF-8 DXF generation applies from this generation in `ezdxf`. |
| `AC1018` | R2004 | 지원 | 지원 | Fully accepted as input. |
| `AC1015` | R2000 | 지원 | 지원 | Fully accepted as input. |
| `AC1009` | R12 | 지원 | 지원 | R12 is accepted, but modern entity semantics may be absent. |
| `AC1012`, `AC1014` | R13, R14 | 제한지원 | 미지원 as native output | Accepted as read-only compatibility input. Normalize/export as a supported modern DXF target. |
| Older than R12 | Pre-R12 | 제한지원 | 미지원 as native output | Accept only as best-effort input. Require warning and audit trail. |
| Binary DXF | Version dependent | 제한지원 | 제한지원 | Accept if `ezdxf` can read it. If parsing fails, require ASCII DXF re-export by the user. |
| Corrupt/non-conforming DXF | Version dependent | 제한지원 | 미지원 | Try recover path only if explicitly implemented and tested. Otherwise reject with diagnostics. |

Required user-facing behavior:

- If the file parses successfully, version alone must not block comparison.
- If a version is limited-support, the report must surface a warning.
- Unsupported entity counts must be exposed through suppression/audit metadata, not silently ignored.
- Output DXF generated by cloud-mark/export features should target `AC1032`/R2018 unless an explicit downstream CAD compatibility profile requires R2013/R2010/R2007.

## DWG Version Policy

DWG is a proprietary native CAD format. After ODA removal, direct DWG ingestion
is allowed only through the internal read-only reader scope below. It must not
use ODA binaries or GPL/AGPL-derived code.

| DWG source version | Native product policy | Allowed workflow | Notes |
| --- | --- | --- | --- |
| R2000 (`AC1015`) | 제한지원 / engineering preview | Internal read-only reader for simple 2D layer/block/model-space entities; otherwise user converts to DXF | `DwgNativeAc1015Adapter` is the first native MVP. Legal/product sign-off is still required before broad support claims. |
| R2004 (`AC1018`) | planned, 미지원 until implemented | User converts to supported DXF | Next extension target after AC1015 validation. |
| R2007 (`AC1021`) | planned, 미지원 until implemented | User converts to supported DXF | Extend after AC1018. |
| R2010 (`AC1024`) | planned, not implemented | User converts to an accepted DXF version | Extend after AC1021. |
| R2013 (`AC1027`) | planned, 미지원 until implemented | User converts to supported DXF | Extend after AC1024. |
| R2018 (`AC1032`) | planned, not implemented | User converts to an accepted DXF version | Extend after AC1027. |
| R13/R14 | 미지원 for embedded direct read | User converts to supported DXF outside the product | Result inherits DXF limited-support constraints after conversion. |
| Newer than R2018 | 미지원 | User exports DXF R2018/R2013/R2010 from CAD authoring tool | No product support until real samples and parser behavior are validated. |
| Encrypted/password-protected DWG | 미지원 | User must provide unencrypted DXF | Do not attempt bypass or recovery. |
| Proxy/custom object-heavy DWG | 미지원 for direct read | User exports exploded/plain DXF or CAD-reviewed DXF | Comparison is limited to entities available in the exported DXF. |

Legacy behavior in this repository:

- `src/services/comparison/dwg_converter.py` still wraps ODA File Converter.
- `DwgDiffer` routes CAD comparison through the CanonicalDrawing pipeline by
  default; ODA conversion is optional legacy fallback only.
- This path is legacy compatibility only and is not approved for product
  embedding after ODA removal.

Post-ODA release rule:

- Customer builds must not bundle ODA binaries.
- Customer builds must not invoke ODA automatically.
- `.dwg` selection in the UI may expose AC1015 native-reader preview only if the
  user-facing status clearly marks partial/unsupported imports.
- Any future direct DWG support beyond AC1015 must have a documented license
  basis, conformance test set, and legal sign-off before release.
- ADR-004 is the accepted roadmap for AC1032/all-version native DWG support:
  current AC1018+ workflow remains user-provided DXF, with converted-DXF
  fallback allowed only when provenance is visible in run artifacts.

## Format Pairing Policy

| Pair type | Policy |
| --- | --- |
| DXF vs DXF | 지원, subject to entity matrix. |
| DWG vs DWG | 제한지원 only when both files are within the native reader's AC1015 simple-2D scope; otherwise convert to DXF first. |
| DWG vs DXF | 제한지원 only when the DWG side imports through the native reader; otherwise convert DWG externally first, then compare DXF vs DXF. |
| CAD vs PDF | 미지원 as entity-level comparison. Use separate visual/PDF workflows only when explicitly implemented. |
| PDF vs PDF | Outside this CAD policy. Governed by PDF comparison policy and third-party license policy. |

## Operational Limits

| Area | Policy |
| --- | --- |
| Entity count | Default dynamic cap applies. If cap is exceeded, report `limit_exceeded` and omitted counts. |
| Block expansion | Default `expand_blocks=True`. If disabled, report block-geometry skipped counts. |
| Paperspace | Default `extract_all_layouts=True`. If disabled, report skipped paperspace entity counts. |
| Coordinates | Compare in drawing units after normalization. Structural layers use stricter position threshold. |
| Preview rendering | Preview may use lightweight mode and omit heavy visual-only entities. Entity diff remains authoritative. |
| Fonts and text rendering | Text comparison uses normalized text content/position. Visual glyph fidelity is not guaranteed. |

## 법무 검토 필요

The following items require legal review before release:

| Item | Reason | Required decision |
| --- | --- | --- |
| Any ODA File Converter use | ODA states non-members may use free downloads only for non-commercial applications; redistribution is not provided as a simple product right. | Remove, disable, or obtain appropriate ODA membership/license. |
| Any ODA SDK integration | Proprietary SDK and membership/license terms. | Approve contract, redistribution, support, and customer deployment rights. |
| Any DWG reverse-engineering implementation | DWG is proprietary and may involve patent/trademark/contract risk. | Approve design, provenance, and distribution posture. |
| Any GPL/AGPL DWG library, including LibreDWG | Strong copyleft can force incompatible product licensing. | Prohibited unless the whole product licensing strategy changes and legal approves. |
| Any cloud/service DWG conversion backend | May trigger SaaS/network obligations for AGPL tools and commercial-use restrictions for proprietary tools. | Approve architecture and license terms before implementation. |
