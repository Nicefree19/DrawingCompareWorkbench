## 1. 문제 — 3자 카운트가 3~5배 갈렸다

| 기준 | 변경전 A | B | C | 변경후 A | B | C |
|---|---:|---:|---:|---:|---:|---:|
| 🧑 인간작업 | **541** | 60 | 3,855 | 66 | 30 | 2,585 |
| 🤖 코덱스 | 161 | 20 | 1,133 | 45 | 15 | 759 |
| 🤖 클로드 | 161 | 20 | 1,368 | 33 | 15 | 530 |

코덱스·클로드는 **총계가 161/20으로 동일**(같은 `보강A/B` 블록을 셈)한데 사람은 541/60.
이건 우연이 아니라 **셋이 서로 다른 단위를 셌다**는 증거다.

## 2. 근본 원인 — "카운트 실수"가 아니라 "모델 오류"

- **사람** = 물리 **개소(PC보 단부)** 를 셈. 대칭 건물이라 **반쪽만 세고 ×2 확장**, C는 **세지 않고 총−A−B 잔여**.
- **AI** = 도면 **표식 객체**(보강A/B 마크·원 심볼·CAD 블록)를 직접 카운트. 대칭 관례·잔여 규칙 누락.

### 결정적 증거 — 인간작업 엑셀의 실제 수식(직접 확인)
```
총개소  R = Q*2 + P            (대칭구간 Q ×2 + 중앙 P)
A타입     = (G - H)*2 + H       (구간 확장; G=측정면 포함, H=중앙)
B타입     = (J - K)*2 + K
C개소     = R - A - B           (잔여 — 직접 카운트 아님)
SUM       = A + B + C  ( = R )
```
→ **사람 파일은 카운트 시트가 아니라 "수량 회계 장부"**다.

### 보조 증거
- 사람 총 SUM(4,456) ≈ 도면 전체 원 심볼 수(4,558, 클로드 실측) — 사람은 심볼/단부 단위로 셈.
- 사람 A(541) / AI 마크(161) ≈ 3.36배 — 마크 1개가 실제 여러 단부를 대표.
- 코덱스는 한 도면에서 `보강A`=33 **과** `M___3`=21 **두 답**을 동시에 발견 — 표현 다중성.

## 3. 고차원 인사이트

1. **수량은 도면에 없다 — 관례(convention)에 있다.** `×2 대칭확장`은 도면이 **절반만 그리고** 나머지를 "읽는 사람이 구조 대칭을 안다"에 위임함을 뜻한다. 물량의 절반은 **픽셀·CAD 어디에도 없다.** 정답 = (도면) ∩ (암묵적 도메인 관례). ⇒ "AI야 도면 보고 세라"는 **원리적으로 미결정** 문제.
2. **AI 실패는 계산이 아니라 의미 접지(semantic grounding).** 161개 블록은 정확히 161개 맞다 — 다만 계약 단위가 아니었다. AI는 *기계 가독성*을 *의미 정합성*보다 우선했다.
3. **"정확"은 단위 정의를 공유해야 성립.** 서로 다른 것을 각자 정확히 세면 영원히 수렴하지 않는다.
4. **재현성**: 같은 소스(161)라도 층 배정 규칙이 암묵적이면 두 AI가 발산(6F: 코덱스79/클로드48). 결정성은 도면-접지 명시 규칙에서만.
5. **AI의 올바른 역할**: 자율 카운터(❌, 자기 단위로 발산)가 아니라 **사람의 검증된 회계 방법론을 자동 복원·검증하는 증폭기(✅)**. 단위·정답앵커는 사람이 1회 고정, AI가 전 층·전 도면에 무결 적용·대사.

## 4. 엔진 아키텍처 (3계층)

```
 [1] 입력/검증 EXTRACTION
        · 권위 출처(인간작업 장부/부재표/도면 물량표)에서 P/Q/G/H/J/K 또는 최종 A/B/총 입력.
        · DXF/비전 지오메트리는 cross-check only / 교차검증 신호로만 사용.
        · 보강 A/B 마크는 최종 수량이 아니라 G/J 후보 또는 검증 신호.
        · 총개소 R/P/Q는 지오메트리 자동 산출 금지. C는 여기서 세지 않는다.
        ⚠ 3자 발산 지점. 권위 출처 없이는 최종 수량 emit 금지. [정책 확정]
                    │  (side/center per zone)
                    ▼
 [2] 회계 ACCOUNTING      반쪽 측정값 → 대칭확장 → A/B/총 → C=총−A−B → SUM
        · expand_side_center(G,H)=(G-H)*2+H
        · expand_center_side(P,Q)=Q*2+P
        · C = R - A - B                                  [검증 완료 ✓]
                    │
                    ▼
 [3] 대사 RECONCILE       회계 산출 vs 인간작업 골든 → 층별 PASS/FAIL
        · 2~3개 층 먼저 재현 → 통과해야 전 층 확장       [검증 완료 ✓]
```

## 5. 검증 현황

**[2]·[3] 계층 = 검증 완료.** `quantity_accounting_engine.py --reconcile 인간작업.xlsx`:
```
층   A(엔진/골든) B(엔진/골든) 총(엔진/골든) C(엔진/골든) 판정
3F   52/52       12/12       476/476      412/412     PASS
6F   285/285     26/26       948/948      637/637     PASS
...  (8개 층 전부)                                    ALL PASS ✓
```
→ 사람의 반쪽 측정값을 엔진에 넣으면 사람 최종값이 **정확히 재현**. **회계 모델은 확정.**

**[1] 계층 = 남은 과제.** 반쪽 측정값(side/center, 타입별)을 CAD에서 자동 추출하는 부분.
이게 에이전트들이 발산한 지점이며, 반드시 **골든 대사로 단위·타입·대칭축을 보정**한 뒤 구현한다.

## 5.5 추출 계층 캘리브레이션 (2026-07-02 확정 — 3자 협업)

두 가지가 **골든 대사로 검증**됐다:

**(가) Geometry Anchor Non-Viability — 지오메트리 총개소 앵커 = 비viable (증명됨).**
층별 `원/사람R` 비율이 0.13~2.36으로 완전 비균일(10F 0.13·9F 0.48 등).
3F가 맞은 건 우연에 가까운 부분 일치다. ⇒ **총개소(P/Q/R)는 지오메트리로 자동 산출하지 않는다.**
권위 출처(사람 장부/부재표/도면 물량표)가 필요하며, 지오메트리는 **cross-check only / 교차검증 전용**이다.

실제 before-DWG `3F보강`~`10F보강` 블록을 재귀 전개한 프로브:

| 층 | 원(CIRCLE) | 긴선 보후보(LINE≥300) | 사람 R | 원/R | 긴선/R |
|---|---:|---:|---:|---:|---:|
| 3F | 960 | 952 | 476 | 2.02 | 2.00 |
| 4F | 520 | 520 | 220 | 2.36 | 2.36 |
| 5F | 759 | 692 | 692 | 1.10 | 1.00 |
| 6F | 763 | 724 | 948 | 0.80 | 0.76 |
| 7F | 640 | 640 | 508 | 1.26 | 1.26 |
| 8F | 628 | 628 | 640 | 0.98 | 0.98 |
| 9F | 224 | 224 | 464 | 0.48 | 0.48 |
| 10F | 64 | 64 | 508 | 0.13 | 0.13 |

근거 파일: `out/p5_geometry_anchor_viability_20260702/geometry_anchor_viability_report.md`.

**(나) A/B 마크 = 최종값이 아니라 중간 앵커 `G/J`(측면 존).** 전 층 사슬 검증 PASS:
```
visible_A_marker × 2 = G           (5F~10F, 측면 존)
visible_B_marker × 2 = J           (5F~7F)
(G - H)*2 + H = 최종 A             (전 층)     ← H = 중앙(F) 존
3F 예외: visible_marker × 2 = 최종  (G/H 분해 없음)
```
즉 마크는 **이중 대칭확장의 1단계**(마크→×2→G→(G-H)×2+H→최종). 마크만으론 최종 불가.
**빠진 것 = H/K(중앙 보정) + P/Q(총량 분리).** 그리고 **정확한 층배정 필수**(마크×2=G가
성립하려면; 예: 6F는 코덱스 79가 정답, 클로드 48은 오배정).

**(다) scope mismatch**: 변경후 10F A 마크는 사람 장부상 빈 행인데 산출물엔 잔존 →
stale/deleted로 분류(객체 존재 ≠ 유효 수량, 재확인).

### 확정된 추출 아키텍처 — "존 기반 추출기"
```
대칭축(그리드 중앙열) 검출
   → 마크를 측면/중앙 존으로 분류
   → 측면 마크 ×2 = G/J   (검증됨)
   → 중앙 마크        = H/K   (구현·검증 필요)
   → P/Q/R(총량)     = 권위 출처 입력(지오메트리 비viable)
   → 지오메트리       = 교차검증/이상치 플래그 전용
   → 회계 엔진: A=(G-H)*2+H, C=총-A-B   (검증됨)
```

## 6. 다음 단계

1. **권위 출처 입력 확정**: 총개소 `P/Q/R`와 최종 또는 중간 `A/B/G/H/J/K`는 인간작업 장부·부재표·도면 물량표에서 받는다.
2. **지오메트리 교차검증**: 원/긴선/마크 수는 권위 출처와 비교해 이상치 플래그만 만든다. 최종 수량으로 승격하지 않는다.
3. **A/B 마크 보조 사용**: 검증된 범위에서 `visible_marker × 2 = G/J` 후보로만 저장한다. `H/K` 없이는 최종 A/B를 계산하지 않는다.
4. **골든 회귀**: 권위 출처 입력 → 회계 엔진 → 사람 골든과 대사. 통과 후에만 전 층 산출.
5. **불변식**: C 직접 카운트 금지. 총·A·B만 권위 출처/회계로 확정하고, C는 `총-A-B`로 계산.
