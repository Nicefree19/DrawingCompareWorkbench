# 사내 파일럿 — 배포 전 스팟체크 기록 (B1)

> 목적: "내가 이미 아는 변경"이 있는 실도면 쌍 3~5개로 검출 누락 여부를 확인하고 기록한다.
> 이 기록이 곧 release-readiness 의 operator dry-run 증빙이며, 향후 정량 정확도(ground truth)의 시작점이 된다.

## 방법 (쌍당 ~5분)

1. 변경 내용을 알고 있는 도면 쌍(이전/개정)을 워크벤치로 비교
2. 알고 있는 변경 각각에 대해: 리스트/구름마크에서 **찾았는지**, **위치가 맞는지** 확인
3. 알지 못했던 검출이 있으면 진짜 변경인지 1~2건만 역확인 (가짜 변경 식별)
4. 아래 표에 기록

## 기록 표

| # | 도면 쌍 (이름/번호) | 아는 변경 (내용 한 줄) | 검출됨? (Y/N) | 위치 정확? (Y/N) | 가짜 변경 눈에 띔? (없음/소수/다수) | 비고 |
|---|---|---|---|---|---|---|
| 1 | | | | | | |
| 2 | | | | | | |
| 3 | | | | | | |
| 4 | | | | | | |
| 5 | | | | | | |

## 판정 기준 (배포 가/부)

- **배포 진행**: 아는 변경의 검출 누락 0건 + 위치 오류 0건 (가짜 변경 소수는 허용 — 보조 도구 고지로 커버)
- **보류·수정 후 재시도**: 아는 변경 누락 1건 이상 → 해당 쌍과 누락 내용을 개발 담당에게 전달 (구역 번호/위치/내용)

## 기록 후

- 이 파일 사본을 결과 run 폴더와 함께 보관
- 누락/오탐 사례는 그대로 ground-truth 라벨로 축적 (향후 정량 검증 입력)
