# 사내 파일럿 — 배포 전 스팟체크 기록 (B1)

> 목적: "내가 이미 아는 변경"이 있는 실도면 쌍 3~5개로 검출 누락 여부를 확인하고 기록한다.
> 이 기록이 곧 release-readiness 의 operator dry-run 증빙이며, 향후 정량 정확도(ground truth)의 시작점이 된다.

## 빠른 시작 — 자동 러너 (권장, 쌍당 ~5분)

GUI를 열지 않고 **명령 1줄**로 비교를 돌려 "검출 변경 표 + 정답 스켈레톤"을 자동 생성한다. 운영자는 *아는 변경이 표에 있는지만* 표시하면 된다.

```bash
python scripts/run_pilot_spotcheck.py <이전도면> <이후도면> -o <출력폴더>
# 예) python scripts/run_pilot_spotcheck.py before.dxf after.dxf -o build/pilot_demo
```

산출물 (출력폴더 하위 run 폴더):

- `pilot_spotcheck.md` — 검출된 변경이 자동 나열된 표(위치·타입·한국어 요약·증감)와 운영자 빈칸(아는변경 / 검출 Y-N / 위치정확 Y-N / 비고), 그리고 '누락 기록' 칸.
- `review_ground_truth.csv` — 기존 ground-truth 스키마(`drawing_label,category,summary_contains,source_format,detection_source,bbox_status`)의 정답 스켈레톤. 검출 기반 사실만 채워지고 `notes`에 "운영자 확정" 표시가 붙는다 — **정답을 도구가 지어내지 않으니** 운영자가 아는 변경과 대조해 확정/수정한다.

작성 절차:

1. `pilot_spotcheck.md`의 검출 표에서, 내가 아는 변경에 해당하는 행에 '검출됨?(Y)'·'위치정확?(Y/N)'을 표시한다.
2. 아는 변경이 어느 검출 행에도 **없으면** '누락 기록'에 한 줄 추가한다 (= 검출 누락, 제품의 진짜 미지).
3. 모르는 검출이 있으면 1~2건만 진짜 변경인지 역확인한다.

판정 (자동 러너):

- **배포 진행 후보**: '누락 기록'이 비어 있음(아는 변경 누락 0) + 위치 오류 0.
- **보류·원인 분석**: '누락' 1건 이상 → 해당 쌍과 누락 내용을 개발 담당에게 전달.

> 포맷: DXF/지원 포맷 우선. DWG는 먼저 DXF로 변환 후 입력한다.
> 여러 쌍을 돌렸다면 결과를 아래 '기록 표'에 집계한다.

## 방법 (수동 대안, 쌍당 ~5분)

1. 변경 내용을 알고 있는 도면 쌍(이전/개정)을 워크벤치로 비교
2. 알고 있는 변경 각각에 대해: 리스트/구름마크에서 **찾았는지**, **위치가 맞는지** 확인
3. 알지 못했던 검출이 있으면 진짜 변경인지 1~2건만 역확인 (가짜 변경 식별)
4. 아래 표에 기록

## 기록 표

| # | 도면 쌍 (이름/번호) | 아는 변경 (내용 한 줄) | 검출됨? (Y/N) | 위치 정확? (Y/N) | 가짜 변경 눈에 띔? (없음/소수/다수) | 비고 |

## 판정 기준 (배포 가/부)

- **배포 진행**: 아는 변경의 검출 누락 0건 + 위치 오류 0건 (가짜 변경 소수는 허용 — 보조 도구 고지로 커버)
- **보류·수정 후 재시도**: 아는 변경 누락 1건 이상 → 해당 쌍과 누락 내용을 개발 담당에게 전달 (구역 번호/위치/내용)

## 기록 후

- 이 파일 사본을 결과 run 폴더와 함께 보관
- 누락/오탐 사례는 그대로 ground-truth 라벨로 축적 (향후 정량 검증 입력)
